What this stack provides

Inception deploys a complete WordPress website served over HTTPS. Three services, each in its own container: nginx terminates TLS on port 443 (the only door), WordPress + php-fpm renders the site, and MariaDB stores every post, page and user. They talk over a private Docker network — only nginx is reachable from your machine.

[stats]443|the only open port;3|isolated containers;2|WordPress users;100%|data kept on restart[/stats]

Start and stop

[cmd]make[/cmd] [out]first start provisions everything, builds and launches (~20s)[/out] [cmd]make down[/cmd] [out]stops and removes containers — your data is preserved[/out] [cmd]make restart[/cmd]

Credentials

All passwords live in the secrets/ directory at the project root. If you don't create them yourself, random ones are generated on first make:

filecontains
secrets/credentials.txtWP admin password (line 1), editor password (line 2)
secrets/db_password.txtMariaDB application-user password
secrets/db_root_password.txtMariaDB root password
[cmd]cat secrets/credentials.txt[/cmd]

The two WordPress users: an administrator (username from WP_ADMIN_USER in srcs/.env, default superuser — the subject forbids any name containing “admin”) and an editor (WP_USER, default editor).

[callout type="warn" title="changing passwords"]Credentials are baked into the database and WordPress at first installation. To change them: edit the files in secrets/, then rebuild the data with make clean && make.[/callout]

Where is my data?

Named volumes store everything under /home/dlesieur/data on the host — mariadb/ for the database, wordpress/ for the site files. Data survives make down, make up and reboots. To erase everything and start fresh: make clean && make.
