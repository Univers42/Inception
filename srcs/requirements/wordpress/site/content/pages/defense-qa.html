Docker fundamentals

How does Docker work? Images are immutable layered filesystems; containers are processes isolated with kernel namespaces and limited by cgroups, sharing the host kernel — that's why they start in milliseconds where VMs boot a whole OS.

Why alpine:3.23? The subject demands the penultimate stable Alpine or Debian. Latest stable is 3.24 → penultimate is 3.23. The test suite re-verifies this against Docker Hub live, because the target moves with releases.

Why is pulling ready-made images forbidden? The point is writing the service setup yourself. Every Dockerfile starts FROM alpine:3.23, installs from Alpine packages, copies hand-written config, and sets a custom entrypoint.

NGINX & TLS

Prove only TLS 1.2/1.3 work:

[cmd]openssl s_client -connect dlesieur.42.fr:443 -tls1_2[/cmd] [out]New, TLSv1.2, Cipher is ECDHE-ECDSA-AES128-GCM-SHA256 ✔[/out] [cmd]openssl s_client -connect dlesieur.42.fr:443 -tls1_1[/cmd] [out]no protocols available ✘ (rejected, as required)[/out]

The certificate chain: make setup creates a local Root CA on the host and signs the server certificate (SANs: domain, localhost, 127.0.0.1). Only the server cert/key enter nginx as secrets — the CA key stays on the host because make trust makes browsers trust it.

WordPress & php-fpm

What is php-fpm, and why “without nginx”? A pool of PHP worker processes speaking FastCGI on port 9000. Separation of concerns: the WordPress container runs only php-fpm; nginx forwards .php requests and serves static files itself.

The admin-name rule: enforced, not just documented — the entrypoint refuses to boot with a username containing “admin”, and the suite checks the live database:

[cmd]docker exec wordpress wp --allow-root user list[/cmd] [out]editor editor superuser administrator[/out]

PID 1, crashes & restarts

Why does every entrypoint end with exec? The daemon replaces the shell and becomes PID 1 — it receives Docker's signals directly and no zombie shell fronts it. That's also why following a file forever, a bare shell, an endless sleep and an infinite shell loop are prohibited keep-alive hacks.

[cmd]docker exec nginx ps -o pid,comm[/cmd] [out]PID COMMAND 1 nginx[/out] [cmd]docker exec nginx kill 1 && sleep 5 && make status[/cmd] [out]nginx Up 4 seconds (health: starting) ← auto-restarted[/out] [callout type="info" title="why unless-stopped"]A SIGTERM'd daemon exits gracefully (code 0). on-failure would never revive it — unless-stopped does, while docker stop still stays stopped.[/callout]

Volumes, network, secrets

Named volumes in /home/login/data? Top-level named volumes with the local driver's device option — real named volumes (no service bind mounts) whose data lives at the mandated path. Network? One bridge, service-name DNS, only 443 published. Secrets? Files at /run/secrets, mode 0400 — nothing in env, images or Git.
