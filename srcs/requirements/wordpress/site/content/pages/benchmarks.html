Where the speed comes from

Build time

  • Minimal packages — nginx ships only nginx (certs from the host, sed templating); WordPress needs no wget, no DB client, no unused extensions.
  • Multi-stage parallelism — the WP tarball + WP-CLI download in a side stage that BuildKit runs concurrently with the PHP install; native tar beats PHP unzip.
  • MariaDB trimmed 318→160MB — embedded server, test client and RocksDB/Aria/MyISAM offline tools deleted in-layer (the engines live inside mariadbd).
  • BuildKit cache mounts — .apk files and the WP tarball persist across package-layer changes; Docker 29 discards them under --no-cache, so the cold number stays honest.

Boot time

  • Zero-download first boot — WP core is copied from the image, not fetched.
  • mariadbd --bootstrap — account init without a temporary server.
  • 500ms start-interval healthchecks — readiness detected in half-second granularity instead of 3s ticks, per dependency hop.

Honest methodology

[callout type="info" title="what cold means"]“True cold” = empty layer cache, empty package caches, base re-pulled. The bench wipes its dedicated cache IDs first, and Docker 29 guarantees cache mounts are discarded under --no-cache. Numbers drift badly on a loaded machine — a build measured 16s idle read 24s under load. Benchmark quiet, compare same-session A/B only.[/callout] [cmd]make bench[/cmd] [out]true cold (empty pkg caches) : 13.1s pkg-cached (layers re-run, warm caches) : 6.9s warm build (all confs touched) : 2.0s no-op build (nothing changed) : 0.6s[/out]
