WordPress serves the blog (/blog/) and the wiki (/wiki/) behind the landing (§11.1). Theme, plugin, pinned third-party plugins and content are all baked into the image, so make re or a fresh clone reproduces the site with zero manual steps. Both sites draw from one set of design tokens, srcs/design/ (colours, type scale, motion, self-hosted OFL fonts), which the compose file hands to both builds as the design build context.

srcs/requirements/wordpress/site/
├── install.sh            # boot hook: sync theme, kit and plugins, then seed, wiki, posts
├── plugins.txt           # third-party plugins, "slug version", fetched at build time
├── seed.php              # once: permalinks, the 4 journal posts, menu
├── sync.php              # the one keep-in-step rule for seeded pages (an edit in wp-admin wins)
├── wiki.php              # every boot, idempotent: /blog/, the wiki pages, menu, search index
├── posts.php             # every boot: the guide series of content/posts/series.json;
│                         #   fills the Home page (the front page) once from pages/home.html
├── plugin/inception-kit/ # [term_window] [cmd] [out] [callout] [stats] [arch] [kbd] [badge];
│                         #   wiki.php (/wiki/ routing, tree, prev/next, 301s), hardening.php
│                         #   (sign-in), admin.php (the maintainer's dashboard)
├── theme/inception-terminal/   # one design system with the landing; front-page.php draws /,
│                               #   single-docs.php and page-wiki.php draw the wiki
└── content/
    ├── posts/            # the journal posts; series.json + series/ (the guide series)
    ├── pages/            # curated summaries, also cut into the wiki
    └── wiki/             # generated by tools/wiki (make wiki): one HTML file per page + tree.json
  • Plugins, each pinned in plugins.txt and unpacked into the image by the wp-src stage (nothing is downloaded while a container starts): redis-cache (the object cache of §11.2), wedocs (the wiki's hierarchical docs post type), easy-table-of-contents (the "On this page" box on posts and wiki pages; its CSS is off and the theme draws it), relevanssi (search ranked by relevance across posts and the wiki), code-block-pro (highlighted code blocks for posts written in the editor) and autodescription (The SEO Framework: meta tags and sitemaps). make test-site fails when a running plugin is off its pin.
  • The wiki is cut from these docs, not written twice. tools/wiki/wiki.json maps each wiki page to a heading of DEV_DOC.md, USER_DOC.md or README.md (or to a curated page); make wiki (node in the nodetool image) writes content/wiki/, and make wiki CHECK=1 fails when that copy is stale. wiki.php creates a missing page and refreshes one the repository changed, but never one edited in wp-admin since the last sync: it compares the stored content with the hash it recorded, and a person's edit wins.
  • Routes: /blog/ (the seeded journal page, renamed; /journal/ answers 301), /wiki/<area>/<page>/ (weDocs' slug changed from docs by the kit), and the five doc pages the wiki replaced answer 301 to their wiki page.
  • Writing from wp-admin: WordPress is the authoring interface. The kit components are block patterns (inserter → Patterns → Inception Kit), the editor canvas uses the same tokens (editor.css), and a wiki page is a Docs entry under its parent.
  • The guide series ("Building Inception": start here, the machine, nginx, Docker, credentials, maintaining the site) is content/posts/series.json plus one HTML file per post, kept in step by posts.php with the wiki's rule.
  • Diagrams are Mermaid, never ASCII: a ```mermaid fence in these docs (GitHub draws it too), <pre class="mermaid"> in hand-written content, or the Diagram (Mermaid) pattern in the editor. Mermaid 11.17.2 is unpacked into the theme (assets/vendor/mermaid/, checked against its SHA-256 at build time) and theme.js loads it only on a page that has a diagram, coloured from the tokens; nginx serves its .mjs modules as JavaScript, which mime.types does not.
  • The maintainer: /wp-admin/ (or Sign in on the landing) opens the branded sign-in. The dashboard leads with Write for Inception (new post, new wiki page, arrange the wiki) and The network, which probes every service by its Compose name from inside the wordpress container. Vendor upsells are off, including the promotion weDocs downloads from its own server.
  • Failure isolation: the entrypoint calls install.sh non-fatally; a broken seed can never prevent php-fpm from starting.
  • Gotcha: WordPress runs wpautop/texturize before shortcodes — the kit registers its shortcodes in no_texturize_shortcodes and strips injected <br/> tags, otherwise --flags in commands render as dashes.
