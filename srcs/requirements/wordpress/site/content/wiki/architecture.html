  • All three containers sit on the inception bridge network; they resolve each other by service name through Docker's embedded DNS. Only 443 is published.
  • Naming rules (subject): each image is named after its service (nginx:inception, wordpress:inception, mariadb:inception — never latest), and the containers are named nginx, wordpress, mariadb.
  • Each service is a self-contained build context: srcs/requirements/<service>/{Dockerfile, conf/, tools/entrypoint.sh}.
  • nginx mounts the WordPress volume read-only and serves static assets itself; only .php requests are forwarded over FastCGI.

A fourth container (bonus, §11.1) serves the landing, a static React site with its own nginx on 8090. The edge proxies https://<login>.42.fr/dream/ to it, never the bare domain: the eval sheet opens https://<login>.42.fr/ expecting the configured WordPress site, so / is WordPress's front page (front-page.php, rendering the Home page). The landing shares no volume or secret with the mandatory trio above.
