Inception has to run inside a virtual machine. Ours is not a hand-installed one: it comes from born2root, a builder for the 42 Born2beRoot server, so the machine under the stack can be thrown away and rebuilt identically with one command.

What the machine is

A Debian server with the Born2beRoot rules applied from the first boot: SSH on port 4242 and no root login over it, a firewall (UFW) that opens only the declared ports, a strict password policy and sudo rules, AppArmor, and a monitoring script run by cron. The disk is encrypted with LUKS and split with LVM into separate volumes, so /var, where Docker keeps its images, can grow without starving /home.

Every answer the Debian installer would ask for is in a preseed file that is built into the ISO. The install runs with no screen: the machine's serial console is a file the host reads to follow progress. At each boot the disk is locked, and the host unlocks it by typing the passphrase into the machine's virtual keyboard. A machine counts as ready when its SSH server answers with a banner, not when a port is open: the hypervisor's NAT accepts connections whether or not anything listens behind it.

Sized from one number

SIZE_B2B, in GB, decides the partition layout. Every volume has a floor, a share and a cap, and /var takes the rest. It also decides which tools fit: under 15 GB a minimal set, from 15 the standard one, from 30 the full one. A set that does not fit stops the build and names the smallest size that would hold it. Memory and CPUs default to a share of the host's, and a number larger than the host has falls back to that default, rather than to a machine that never starts.

Two hypervisors, one guest

born2root runs the same ISO on QEMU/KVM or on VirtualBox and picks one by what the host offers (make backend prints the decision and its reasons). Ports are forwarded from the host to the guest from one list, so SSH, HTTPS and the bonus ports reach the machine the same way on either.

[callout type="ok" title="why it matters"]Because the machine is rebuilt from code, a broken guest is never repaired by hand: make re destroys it and builds it again, and make inception puts the stack back on top.[/callout]
