Of the three mandatory containers, only nginx is reachable from outside, and only on port 443. WordPress and MariaDB publish nothing. Every page, image and API answer on dlesieur.42.fr goes through this one door.

Where each path goes

    accDescr: The browser reaches nginx over TLS 1.2 or 1.3 on port 443. nginx sends /dream/ and /_dream/ to the landing on staticsite:8090, /lab/ to web:8080, /api/v1/ to api:3000, and everything else to WordPress on port 9000 over FastCGI.
    browser(["Browser"]) -->|"TLS 1.2 / 1.3 on :443"| nginx["nginx"]
    nginx -->|"/dream/ and /_dream/"| landing["staticsite:8090<br/>the landing"]
    nginx -->|"/lab/"| web["web:8080<br/>the lab"]
    nginx -->|"/api/v1/"| api["api:3000<br/>JSON"]
    nginx -->|"everything else, FastCGI"| wordpress["wordpress:9000<br/>blog, wiki, wp-admin"]

The bare / is WordPress's front page: the evaluation opens it expecting the configured WordPress site, so no bonus may stand in for it. The landing, built with React and served by its own small nginx in the staticsite container, answers one link away at /dream/; nginx swaps that prefix for the staticsite's own / on the way. /, /blog/, /wiki/ and /wp-admin/ fall through to WordPress: nginx hands .php requests to php-fpm over FastCGI on port 9000 and serves the static files itself, read-only, from the volume they share.

TLS, and nothing older

The server accepts TLS 1.2 and 1.3 only (ssl_protocols), with an ECDSA P-256 key and a modern AEAD cipher list, and hides its version (server_tokens off). The certificate is issued on the host by a local certification authority, and the CA's private key never enters a container: nginx receives the server certificate and key, nothing more.

Keeping connections, not opening them

The lab's upstreams keep a pool of open connections instead of opening one per request. The reason is a measurement: with one connection per request, every closed socket waits a minute in TIME_WAIT, and 3 300 requests a second to /api/v1/ filled the whole local port range (28 267 sockets) in 9 seconds. nginx answered 502 until they expired. Upstream names are re-resolved through Docker's DNS, so a recreated container is found again without restarting nginx.

What the door refuses

  • Password guessing: sign-in attempts (POST /wp-login.php) are limited to 10 a minute per address with a burst of 5, then answered 429.
  • XML-RPC: /xmlrpc.php answers 403. Nothing here uses it, and it could try hundreds of passwords in one request.
  • Framing and sniffing: pages may only be framed by the site itself (frame-ancestors 'self'), and browsers must not guess content types (nosniff).
[callout type="warn" title="no HSTS, on purpose"]A browser applies HSTS to the whole host name, ports included, and the static site's bonus port 8090 is plain HTTP. Turning HSTS on would make that port unreachable from any browser that had visited the HTTPS site.[/callout]
