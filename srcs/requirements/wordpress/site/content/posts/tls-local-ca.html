Self-signed certificates mean browser warnings forever. A local certification authority means a real padlock — but it also means you've created a key that can impersonate any website to every browser that trusts it. Where that key lives becomes the whole design.

The first version had it backwards

The CA keypair was mounted into the nginx container, which signed its own server certificate at boot. Convenient — and wrong: make trust installs that CA into the system and browser trust stores. Compromise the container, steal the CA key, and you can mint github.com.

Sign on the host, ship only the leaf

make setup now issues everything host-side: a 10-year Root CA, then a server certificate for the domain with proper SANs (domain, localhost, 127.0.0.1). Only the server cert and key enter the container — as Docker secrets, mode 0400:

[term_window title="secrets/"] [out]ca.key ← never leaves the host ca.crt ← what `make trust` installs server.key → nginx (secret, 0400) server.crt → nginx (secret, 0444)[/out] [/term_window]

Bonus effects: openssl disappeared from the nginx image entirely, boots got faster (no per-boot cert generation), and the certificate is re-issued automatically when DOMAIN_NAME changes — the SAN is checked against srcs/.env on every make up.

Proving it

[cmd]openssl s_client -connect dlesieur.42.fr:443 -tls1_3 | openssl x509 -noout -subject -issuer[/cmd] [out]subject= CN = dlesieur.42.fr issuer= CN = Inception Local CA[/out] [callout type="warn" title="lesson"]A browser-trusted CA key is the most dangerous secret in the project — architecture must guarantee it never crosses a container boundary.[/callout]
