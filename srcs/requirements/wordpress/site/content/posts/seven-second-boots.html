From docker compose up -d to a live HTTPS WordPress in 6.8 seconds — on completely fresh volumes, database initialisation and WordPress installation included. Here's where the 11.4-second chain was hiding its fat.

Dead time #1: healthcheck ticks

Checks ran every 3 seconds — so each dependency hop (mariadb → wordpress → nginx) wasted up to 3s just noticing readiness. Docker's --start-interval=500ms polls twice a second during startup while keeping the relaxed cadence afterwards.

Dead time #2: the temporary server dance

Classic MariaDB init: start a throwaway --skip-networking server, poll until it answers, run the account SQL, shut it down, start the real one. Replaced with bootstrap mode — SQL applied directly, no server lifecycle, no client, no auth:

[cmd]mariadbd --user=mysql --bootstrap <…which is how I learned that bootstrap mode doesn't load the grant tables. The fix is delightfully arcane: make FLUSH PRIVILEGES; the first statement — it loads the tables, after which ALTER USER and GRANT are legal. That gotcha is now documented in three places so nobody “cleans it up”.

Dead time #3: PHP boots nobody asked for

wp config create spends ~0.6s booting PHP to write a config file a heredoc writes for free (salts generated locally, passwords escaped). And the full-tree chown -R over ~2600 files became a targeted find -user root — the copied core already carries the right ownership from the image.
